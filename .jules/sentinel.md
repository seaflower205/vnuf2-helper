## 2025-01-20 - Fix Hardcoded Cryptography Key in Browser Extension Storage
**Vulnerability:** A hardcoded symmetric encryption key (`VNUF2Helper2026`) was used to obfuscate user credentials stored in `chrome.storage.local`. This violates the standard of not keeping static secrets in code, as any attacker with local access (and knowledge of the open-source extension) could immediately decrypt the passwords.
**Learning:** For browser extensions, adding a fake layer of cryptography using a hardcoded key provides a false sense of security (security theater). However, we can legitimately improve security by generating a secure, random symmetric key per-install (`crypto.getRandomValues`) and storing it securely within the extension's isolated storage context, making mass decryption via hardcoded keys impossible.
**Prevention:** Avoid hardcoded secrets even for local obfuscation. Utilize asynchronous storage APIs (`chrome.storage.local`) combined with native Web Crypto APIs to dynamically generate keys per installation. Always implement version prefixing (like `v2:`) to ensure backward compatibility for legacy encrypted data when rolling out crypto improvements to avoid data loss.
