## 2025-02-14 - Prevent ICS Format Injection in Calendar Export
**Vulnerability:** Calendar export functionality (`generateICS`) inserted unsanitized user-generated data (e.g., class names, locations) into the `.ics` file. This could allow an attacker (or malformed input) to inject malicious calendar events or execute arbitrary commands within calendar clients by breaking out of the designated field using unsanitized newline characters (`\r\n` or `\n`).
**Learning:** ICS files (RFC 5545) are text-based and rely heavily on newlines (`\r\n`) to delimit properties and components. When inserting text like "description" or "summary", special characters—particularly `,`, `;`, `\`, and newlines—must be explicitly escaped to prevent the structure from being manipulated.
**Prevention:** Always implement a dedicated sanitizer function (e.g., `escapeICS`) that correctly escapes reserved characters (`\`, `;`, `,`) and converts standard newlines (`\n`) to literal string escapes (`\n`) when constructing structured text formats like ICS or CSV from arbitrary data.
